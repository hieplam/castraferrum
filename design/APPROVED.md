# Castraferrum - design approvals

Every UI pull request (the phase 1 screens and later) must match what is approved here. Changing an approved design means
asking the project owner again and adding an entry to this file.

## the design system - design system direction C "Control room", 2026-10-18

Approved: the token file [`tokens.css`](tokens.css) (the only token file), the components in [`components.css`](components.css)
(Button, Field, Segmented, FilterTabs, StatusTag, ListRow, KvGrid, LogView, DataTable, Banner, EmptyState, Skeleton, Dialog,
Menu, Toast), the design-system page [`system/index.html`](system/index.html) (light and dark side by side), the sample layout
[`system/layout.html`](system/layout.html) (top bar, fixed 520px list on the left, main pane by path) and the UI kit for the app:
shadcn/ui with Tailwind v4 (tokens are CSS variables of `tokens.css`).

Fonts: IBM Plex Sans (loop names, prose) and IBM Plex Mono (numbers, times, ids, labels, buttons, logs). One accent colour: amber.

Path of the brainstorm: three directions for the list screen (A compact table, B cards, C control room); the owner chose C and
asked for a complete design system for C. The early exploration files were removed from the repository; they stay in git history.

Owner's words: "build a proper design system with tokens, fonts, layout, then let me choose"; "wait, focus on C, I like the layout of C
more (approve C)"; "approved. no need for a preview, decide it in another issue".

0 pixels difference in all 10 shots (threshold 0.1 %).

## Run summary - run summary on the run row, 2026-10-19 (app built 2026-10-20)

Approved by the coordinating session under the owner's delegation of 2026-10-19, without changes (preview PR). Chosen:
a sub-row under every run in the run history and in the runs of an execution, capped at 80 characters (code points) with an
ellipsis, the full text in the `title`, a dim dash when there is no summary, a run where the agent skipped itself still shows
Succeeded; the "latest runs" table has no sub-row. Decisions D-UI22 to D-UI26 are in [`STATES.md`](STATES.md). Evidence: e2e
`@UC-31` and `tests/visual/detail.visual.ts` (threshold 0.1 %).

## Max parallel runs - "Max parallel runs" field and the text for several running runs, 2026-10-20

Approved under the owner's delegation of 2026-10-19; the owner asked for the feature on 2026-10-20. No new preview
states: the field appears in every existing `form-*` state, and the multi-run text only shows when a loop has N > 1 (all preview
data has N = 1). Chosen: a number field **Max parallel runs** (unit: runs, default 1) right after **Timeout per run** in the
Execution section, for the Claude executor and for Mock, reusing `.field` and `.affix` with no new CSS. When N > 1: the detail
title reads "3 runs in progress" with the round numbers, the sub-line and the Executor cell of the config get "parallel up to N",
list rows get a count after the round and time, and the Stop confirmation names the runs that will be cancelled. Evidence:
`tests/visual/form.visual.ts` and e2e `@UC-32`.
