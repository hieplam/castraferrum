# Spec: UI uplift - a mobile-first redesign and a design system that keeps the UI consistent

- Date: 2026-10-21
- Status: approved by the owner in conversation (brainstorm rounds 1 and 2, 2026-10-21: "I approve all"); the owner
  reviews this document after merge
- Epic: [#63](https://github.com/hieplam/castraferrum/issues/63)
- Plan: [../plans/2026-10-21-ui-uplift.md](../plans/2026-10-21-ui-uplift.md)
- Approved reference: [`design/reference/`](../../design/reference/README.md) (exports of the approved brainstorm canvas)

## 1. Context

The owner finds the console hard to use. The text is small (body 13px, most of the UI 12px monospace, labels 11px
uppercase at 2.45:1 contrast). The layout is dense: one long loop page stacks stats, latest run, an Executions table,
a Run history table, configuration and prompt. A newcomer cannot tell an execution from a run. Native `title`
tooltips look foreign in dark mode. Hover and highlight colours are wrong in dark mode. The measured findings F1 to F7
are in epic #63. The worst is F1: four dark tokens in `design/tokens.css` lost their values, so hovered rows turn beige
with text at 1.10:1, and the approved dark reference shots were taken with the bug in them (F2).

The brainstorm (2026-10-21) gave the owner three looks and two layouts. Then the vision changed: the next features
focus on mobile (iPhone), so the redesign is **mobile-first**. The owner chose:

- **Look C "Soft studio"**: a teal accent, rounded corners, Be Vietnam Pro for words and JetBrains Mono for numbers,
  ids and logs. The light theme uses a **paper** background ("a feeling like reading a book"), and the dark theme is a
  near-black green.
- **Pages** instead of the permanent list-and-detail split, because they fit a phone.
- **"Active period"** as the name of the Start-to-Stop span (the API keeps `execution`).
- **Order**: a hotfix of the dark tokens first, then the redesign, then the phone work. The phone layout of #47
  (L3 to L5) is part of this epic.
- **A hard rule for the future**: every UI change, however small, starts from the design system, and a gap in the
  system becomes a tracked issue. This needs a design system that is written down, not only CSS.

## 2. Decisions

| # | Decision | Why |
|---|---|---|
| D1 | **Mobile-first.** The phone layout (below 640px) is the base. Tablet (640 to 1023px) and desktop (1024px and up) show the same pages and the same components, with more room. | The next features are mobile. One design at two densities is cheaper to keep consistent than two designs. |
| D2 | **Look C with a paper light theme.** Colours, type and sizes are the tokens in section 4. Four colours differ from the canvas, adjusted so every pair passes WCAG AA with the new pressed state: light `--text-subtle` `#6b624f` becomes `#665d4a`; dark `--text-subtle` `#8a9a95` becomes `#94a49f`; dark `--selected` `#15403a` becomes `#133a34`; dark `--border-strong` `#6a7b75` becomes `#74867f`. | The owner chose C and asked for paper. The adjustments are invisible at a glance but keep the contrast rule true for every state. |
| D3 | **Fonts:** Be Vietnam Pro 400/500/600/700 (`@fontsource/be-vietnam-pro` 5.3.0) and JetBrains Mono 400/500/600 (`@fontsource/jetbrains-mono` 5.3.0), self-hosted like IBM Plex today. The preview pages load the same families from Google Fonts. | Both cover Vietnamese (the owner's loop names use diacritics), and both are pinned like the existing font packages. |
| D4 | **Type:** desktop body 15px, phone body 16px; every text field is 16px on every screen size. The smallest text is 13px, except tab bar labels at 12px. No uppercase labels with letter spacing: sentence case everywhere. Numbers, ids, times, paths and logs use the mono font; words use the sans font. | The owner said the text is too small. iOS Safari zooms into any field under 16px. Uppercase 11px labels were the worst contrast offenders. |
| D5 | **Navigation by pages.** Phone: a bottom tab bar (Loops, Repos, Settings); pages push from the list with a back button in a navigation bar; tab roots have a large title. Tablet and desktop: a top bar with the brand, the same three links, the connection status and a theme button; page content up to 1200px wide; a back link above the page title. | Pages fit a phone; the permanent 520px list was the main reason the layout felt cramped. |
| D6 | **Naming:** the UI says **active period** where it said execution, in English and Vietnamese. API routes, database names and DTO fields keep `execution`; the page URL stays `/executions/:id`. The Executions table and the Run history table are replaced by one **Recent runs** list grouped by active period, an **All runs** page and the active period page. | Newcomers did not understand "Executions" next to "Run history". | D7 | **Status is a dot and a word** in a pill, never a glyph alone (`✓23 ✗0 ⊘0 ↷1` goes away). Mapping in section 4.7. | Glyph counts had no legend. |
| D8 | **Interaction states** are defined once (section 4.4): rest, hover, pressed, selected, focus, disabled. | D9 | **No hover-only control.** Every control is visible at rest. On the phone layout every tappable target is at least 44 by 44 CSS pixels; each loop row shows Start or Stop as a visible button. | Touch has no hover; #47's D6 asked for the same. |
| D10 | **No information lives only in a tooltip.** The tooltip component labels icon-only buttons on pointer devices: it opens on hover and on keyboard focus, closes on Escape, uses `aria-describedby`, and never appears on touch. Explanations use a **toggletip**: a `?` button opens a popover on desktop and a bottom sheet on the phone, on click or tap. Native `title` attributes are not used anywhere. | The owner said tooltips in dark mode looked foreign; the run summary was readable only by hovering. |
| D11 | **Menus and confirmations** are one component each that renders as a popover menu or a centred dialog from 640px, and as a bottom sheet below 640px. | Thumb reach on the phone, a familiar pattern on the desktop. |
| D12 | **Lists, not tables, on the phone.** The desktop Loops page keeps columns; every other list (runs, repos, periods, folders) uses the inset list on every screen size. | Tables overflow on 390px; one list component keeps both layouts consistent. |
| D13 | **iOS and installability:** `viewport-fit=cover` with safe-area insets on the bars, dynamic viewport units, `theme-color` set from the current theme, `-webkit-tap-highlight-color: transparent` with our own pressed state, a web app manifest (standalone) and an apple-touch-icon. On the phone layout, Settings explains Add to Home Screen. | The owner asked for iPhone; the approved Settings board shows Add to Home Screen. |
| D14 | **Settings page** (`/settings`, new): theme (Automatic, Light, Dark), language, connection (server, database, console address) and version. On the desktop the top bar also keeps a theme button. | The phone has no top bar for the old toggles; the approved board shows this page. |
| D15 | **Copy to clipboard works over plain HTTP.** A copy helper uses `navigator.clipboard` when the page is a secure context and falls back to a hidden textarea and `document.execCommand('copy')` otherwise. | On a phone over the local network (#47) the console is `http://<ip>`, where `navigator.clipboard` does not exist. |
| D16 | **Plural-aware texts.** A key that counts something has `.one` and `.other` forms (and `.zero` where the design shows a word for zero); `web/prefs` gets a `tn(base, n)` helper. | "1 loops" (#27); the new texts count runs, loops and ids everywhere. |

The same e2e suite runs against both UIs. | `main` stays green and usable every day; the owner can try the new UI on the real console before it replaces the classic one. |
| D18 | **The hotfix ships first, on the classic UI.** The four empty dark tokens get these values: `--surface: #121410`, `--surface-sunken: #1e221b`, `--st-skipped-soft: #161913`, `--log-bg: #060705`. No trace of the original values survives (the canvas research found none), so the values follow the existing dark palette: surface between bg and `--surface-2`, sunken one step lighter, the soft skipped tint near surface, the log darker than bg. |

fails for an empty or stub implementation. The baseline numbers are measured by U0 with committed tools, never copied

## 4. The design system

the phone and the desktop, light and dark, the type, colour and states sheet, and `canvas.css` (the literal CSS behind
the boards). `design/ds/` turns it into a token-only system. Where this section and `canvas.css` differ, this section
wins.

### 4.6 Layout rules

- **Frame.** Phone: no top bar; a navigation bar on pushed pages; tab roots (`/`, `/repos`, `/settings`) show a
  large title; the tab bar is fixed at the bottom. Tablet and desktop: the top bar; no tab bar; a back link above the
  page title on pushed pages.
- **Widths.** `.page` is at most `--size-page` (1200px) wide, centred, with `--space-8` side padding (desktop) or
  `--space-4` (phone). `.page.is-narrow` (`--size-page-narrow`, 720px) is used by the editor, the settings page, the
  repos page and the loop settings page.
- **Two columns** (`.cols`) from 1024px: the loop page (activity left, figures and settings right, as
  `d-loop-light.png`) and the run page (summary, transcript and log left; facts, session and resume command right).
- **Actions.** The main action of a page (Start, Stop loop, Restore, Create loop, Save changes, Add repo) sits in
  `.actionbar` on the phone and in `.page-head` (or `.form-foot` for the editor) from 640px. The component renders
  the action once: a `useLayout()` hook in `web/ui/kit/` picks the place, so no test id appears twice.
- **Bottom padding.** A page with a fixed bar at the bottom keeps padding so the last item is never hidden.

### 4.8 Accessibility

Contrast as section 4.3; every interactive element is a real `button`, `a` or form control with a visible label or an
`aria-label`; icon-only buttons get the tooltip on pointer devices and an `aria-label` everywhere; sheets and dialogs
trap focus, close on Escape and give focus back to the opener; the tab bar is a `nav` with `aria-current="page"`;
status pills are text, not colour alone; animations stop under `prefers-reduced-motion: reduce`.

### 4.9 iOS and installability

- `web/index.html`: one `<meta name="theme-color">` whose content the app sets from the computed `--bg` whenever the
  theme changes, a link to `/manifest.webmanifest` and to `/apple-touch-icon.png`. `web/main.tsx` adds
  `viewport-fit=cover` to the viewport meta for the new UI only (the classic UI has no safe-area padding).
- The version on Settings is the `package.json` version, given to the build by Vite `define` (`__APP_VERSION__`).
- `web/public/manifest.webmanifest`: `name` and `short_name` "Castraferrum", `display` "standalone", `start_url` "/",
  `background_color` and `theme_color` the light `--bg` (`#f3ecdc`), icons 192 and 512 px.
- Icons (`web/public/apple-touch-icon.png` 180 px, `icon-192.png`, `icon-512.png`): the brand mark (a vertical teal
  bar, `#0f766e`) on the paper background (`#f3ecdc`), drawn from `web/public/icon.svg` by a committed script.
- The tab bar, the action bar and sheets add `--safe-bottom`; the navigation bar adds `--safe-top`; heights use `dvh`.
- `-webkit-tap-highlight-color: transparent` on `.app`; the pressed state replaces it.
